# Этап 5. Выбор тем студентами

## Цель этапа

Студенты выбирают тему и подают заявку, НР принимает или отклоняет заявки и управляет местами в теме.

## Роли и интерфейсы

- Студент: страница `Выбор темы ДП/ДР`.
- НР: страница `Заявки студентов`.
- Обе роли: карточка темы и статусы заявок.

## API для интеграции

| Метод | Endpoint | Назначение |
| --- | --- | --- |
| GET | `/api/v{version}/Topics/available` | Список доступных тем для студентов. |
| GET | `/api/v{version}/Topics/{id}` | Детали выбранной темы. |
| POST | `/api/v{version}/applications` | Подать заявку (`CreateApplicationRequest`). |
| GET | `/api/v{version}/applications/my` | Мои заявки студента. |
| DELETE | `/api/v{version}/applications/{applicationId}` | Отмена заявки. |
| GET | `/api/v{version}/applications/by-topic/{topicId}` | Заявки по теме для НР. |
| POST | `/api/v{version}/applications/{applicationId}/accept` | Принять заявку. |
| POST | `/api/v{version}/applications/{applicationId}/reject` | Отклонить заявку (`RejectApplicationRequest`). |
| POST | `/api/v{version}/Topics/{id}/close` | Закрыть тему при заполнении лимита мест. |

### Request schema (ключевые)

`CreateApplicationRequest`
- `TopicId: long`
- `MotivationLetter: string?`

`RejectApplicationRequest`
- `RejectReason: string`

## Детальные требования к фронтенду

1. На странице студента реализовать фильтры: тип работы, направление, НР, формат (индив./команда).
2. В карточке темы показывать `AvailableSpots` и блокировать кнопку подачи, если мест нет.
3. После подачи заявки обновлять статус без перезагрузки.
4. Для НР: список заявок по темам со статусами и мотивационным письмом.
5. При `reject` обязательна причина.
6. При достижении лимита участников НР может закрыть тему.

## Бизнес-правила и валидации

- Нельзя подать заявку на закрытую тему.
- Нельзя подать дубликат заявки на ту же тему.
- Переход статуса только по цепочке: `Pending -> Accepted/Rejected`.

## API Gap / Уточнение

- В воркфлоу закрепление студента за темой описано как автоматическое.
  Если backend не создает `work` автоматически, использовать:
  `POST /works` и `POST /works/{workId}/participants` как отдельный шаг.

## Чек-лист делегирования (для сокомандника)

1. Сделать каталог доступных тем и карточку деталей.
2. Подключить подачу/отмену заявки студентом.
3. Реализовать кабинет НР для accept/reject.
4. Добавить закрытие темы по лимиту мест.
5. Проверить уведомления и статусы в обоих кабинетах.

## Definition of Done

- Студент может пройти полный путь от выбора до получения решения.
- НР может обработать заявки без прямого доступа к БД.
- UI корректно учитывает лимиты мест и закрытие темы.
