# Этап 1. Утверждение научных руководителей

## Цель этапа

Сформировать и утвердить состав научных руководителей (НР) по кафедре, открыть им доступ к процессу и отправить уведомления.

## Роли и интерфейсы

- Кафедра: страница `Научные руководители`.
- Кафедра: модалка `Добавить научного руководителя`.

## API для интеграции

| Метод | Endpoint | Назначение |
| --- | --- | --- |
| GET | `/api/v{version}/Users/me` | Получить `DepartmentId` текущего пользователя. |
| GET | `/api/v{version}/Staff?departmentId={id}` | Список сотрудников кафедры для выбора НР. |
| GET | `/api/v{version}/Staff/supervisors?departmentId={id}` | Текущий утвержденный список НР. |
| POST | `/api/v{version}/Staff/approve-supervisors` | Массовое утверждение НР (`ApproveSupervisorsRequest`). |
| GET | `/api/v{version}/Notifications` | Проверка уведомлений после утверждения. |

### Request schema

`ApproveSupervisorsRequest`
- `DepartmentId: int`
- `StaffIds: IReadOnlyList<int>`

## Детальные требования к фронтенду

1. При загрузке страницы брать `DepartmentId` из профиля и грузить сотрудников кафедры.
2. В таблице сотрудников показывать минимум: ФИО, должность, ученая степень, текущий флаг НР.
3. В модалке выбора поддержать множественный выбор и поиск по ФИО.
4. Кнопка `Утвердить состав НР` активна только при выбранных `StaffIds`.
5. Перед `POST /approve-supervisors` показывать confirm modal с количеством выбранных сотрудников.
6. После успеха делать refetch списка НР и показывать success toast.
7. В случае ошибки сервера сохранять выбор пользователя и показывать retry.

## Бизнес-правила и валидации

- Нельзя отправлять пустой список `StaffIds`.
- Сотрудник должен принадлежать текущей кафедре.
- Повторное утверждение того же состава не должно ломать UI (идемпотентное поведение на фронте).

## Чек-лист делегирования (для сокомандника)

1. Собрать UI страницы и модалки выбора НР.
2. Подключить запросы `Users/me`, `Staff`, `Staff/supervisors`.
3. Реализовать submit через `approve-supervisors`.
4. Добавить loading/error/success состояния.
5. Покрыть e2e-сценарии: успешное утверждение, пустой выбор, ошибка API.

## Definition of Done

- Кафедра может выбрать и утвердить НР без ручного обновления страницы.
- После повторного входа отображается актуальный утвержденный состав.
- UX содержит понятные ошибки и подтверждение операции.
