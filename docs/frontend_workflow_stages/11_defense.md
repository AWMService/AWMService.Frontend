# Этап 11. Защита

## Цель этапа

Провести финальную защиту, зафиксировать оценки комиссии ГАК, сформировать итоговые документы.

## Роли и интерфейсы

- Студент: страница `Моя защита`.
- Члены ГАК: страница `Защиты ГАК`.
- Секретарь ГАК: экран протоколирования и финализации.

## API для интеграции

| Метод | Endpoint | Назначение |
| --- | --- | --- |
| GET | `/api/v{version}/defense-schedule?commissionId={id}` | Список защит по комиссии/дню. |
| GET | `/api/v{version}/defense-schedule/{slotId}` | Детали конкретной защиты. |
| POST | `/api/v{version}/works/{workId}/Attachments` | Загрузка материалов защиты студентом. |
| GET | `/api/v{version}/evaluation/criteria?workTypeId={id}` | Критерии оценивания защиты. |
| POST | `/api/v{version}/evaluation/schedule/{scheduleId}/grades` | Оценка от члена комиссии. |
| GET | `/api/v{version}/evaluation/schedule/{scheduleId}/grades` | Сводка оценок для согласования. |
| PUT | `/api/v{version}/evaluation/schedule/{scheduleId}/finalize` | Финальное согласование оценок. |
| POST | `/api/v{version}/protocols` | Формирование итоговой ведомости/протокола защиты. |
| GET | `/api/v{version}/protocols/{protocolId}` | Получить сгенерированный протокол. |

### Request schema (ключевые)

`SubmitGradeRequest`
- `MemberId`, `CriteriaId`, `Score`, `Comment?`

`GenerateProtocolRequest`
- `ScheduleId: long`
- `CommissionId: int`

## Детальные требования к фронтенду

1. На стороне студента показать дату/время/состав ГАК/аудиторию и форму загрузки финальных материалов.
2. Для членов ГАК реализовать форму выставления оценок по критериям.
3. Для секретаря сделать двухшаговый процесс:
   просмотр агрегированных оценок -> `finalize`.
4. После `finalize` блокировать редактирование оценок в UI.
5. Добавить кнопку генерации протокола и скачивания документа.

## Бизнес-правила и валидации

- Оценка должна соответствовать допустимому диапазону критерия.
- Финализация доступна после заполнения обязательных оценок комиссии.
- После финализации изменить оценки нельзя без отдельной административной процедуры.

## API Gap / Уточнение

- В воркфлоу есть часть про перевод студента в статус `Выпускник` и архивный режим.
  В открытых endpoint это как отдельный API не отражено; нужно уточнение backend.

## Чек-лист делегирования (для сокомандника)

1. Реализовать student view защиты и загрузку материалов.
2. Реализовать panel членов ГАК для оценивания.
3. Реализовать panel секретаря для финализации.
4. Подключить генерацию и получение протокола.
5. Добавить тесты на finalize-lock и повторный вход в сессию.

## Definition of Done

- Оценивание и финализация защиты выполняются через UI без ручного вмешательства.
- Итоговый протокол формируется и доступен для скачивания.
- Пользовательские роли видят только свои действия и данные.
