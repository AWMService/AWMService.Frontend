# Department Cabinet Requirements

## Назначение кабинета

Кабинет кафедры управляет всем workflow: НР, периоды, согласования, комиссии, назначения экспертов/рецензентов, допуск и расписание защиты.

## Разделы кабинета

1. Научные руководители.
2. Периоды и сроки (initial + defense).
3. Направления (рассмотрение).
4. Согласование тем.
5. Комиссии (предзащита и ГАК).
6. Распределение студентов по слотам.
7. Назначение экспертов и рецензентов.
8. Готовность к защите и допуск.
9. Уведомления и отчеты.

## Основные сценарии

1. Утверждение НР.
2. Настройка стартовых и защитных периодов.
3. Review направлений: approve/reject/request-revision.
4. Массовое согласование тем и завершение этапа.
5. Создание комиссий, слотов, назначений экспертов.
6. Формирование списка допущенных к защите.

## Функциональные требования

1. Все критичные действия только через confirm modal.
2. Массовые операции должны поддерживать multi-select.
3. Таблицы обязаны поддерживать фильтры по статусам и учебному году.
4. Для периодов обязательна проверка пересечений и порядка дат.
5. Для комиссий обязательны ролевые места (председатель/секретарь/члены).

## Нефункциональные требования

1. Высокая читаемость дашбордов и сводок для принятия решений.
2. Быстрое восстановление состояния после ошибок API.

## Права и ограничения

1. Только роль кафедры имеет доступ к массовым утверждениям и завершению этапов.
2. Изменения действуют в рамках своей кафедры и учебного года.

## Definition of Done

1. Кафедра может пройти полный управленческий цикл без ручной поддержки backend.
2. Состояния и статусы в UI совпадают с API.
3. Все массовые действия защищены валидацией.
