# Student Cabinet Requirements

## Назначение кабинета

Личный кабинет студента покрывает путь от выбора темы до загрузки итоговых материалов на защиту.

## Разделы кабинета

1. Профиль и текущий учебный год.
2. Выбор темы и мои заявки.
3. Моя работа (состав, статус, участники).
4. Предзащита (материалы, попытки, результаты).
5. Проверки (нормоконтроль, ПО, антиплагиат).
6. Рецензия (контакты рецензента, загрузка рецензии).
7. Защита (расписание, материалы защиты).
8. Уведомления.

## Основные сценарии

1. Студент выбирает тему, подает заявку, получает решение НР.
2. После закрепления загружает материалы по этапам и отслеживает статусы.
3. Проходит циклы доработок по проверкам до `Зачет`.
4. Получает допуск к защите и загружает итоговые материалы.

## Функциональные требования

1. В каталоге тем обязательны фильтры: тип работы, направление, НР, формат команды.
2. На карточке темы отображать свободные места и блокировать подачу на закрытую тему.
3. В разделе проверок показывать раздельные статусы по каждому check type.
4. Поддержать многократную загрузку материалов при `Незачет`.
5. После итогового `Зачет` по проверке блокировать редактирование соответствующих вложений.
6. Для предзащиты и защиты показывать дату, время, место, комиссию, регламент.
7. Все long-running операции сопровождать toast + retry.

## Нефункциональные требования

1. Полная поддержка мобильного viewport для критичных действий загрузки.
2. Безопасная работа с файлами (валидация расширений и размера до отправки).
3. Ролевой доступ: студент не видит административные действия кафедры.

## Права и ограничения

1. Нельзя подавать заявку на закрытую тему.
2. Нельзя менять материалы после финальной фиксации этапа.
3. Нельзя менять чужую работу и чужие заявки.

## Definition of Done

1. Студент проходит весь workflow в кабинете без ручной помощи администратора.
2. Все статусы совпадают с backend после перезахода.
3. Негативные сценарии обрабатываются понятными сообщениями.
